# Spec 06 — CI pipeline: hardening and completion

**Issue:** [#6 [Infra] CI pipeline: run the test suite + lint on every PR](https://github.com/oduameh/sherlock-web/issues/6) — **CLOSED** by PR #18 (commit `2bb3d67`)
**Status:** partially shipped; this spec covers the remaining gaps · **Priority:** P0 · **Depends on:** job additions activate when spec 03 lands

## Problem statement

Issue #6 asked for CI running lint + tests + a boot smoke on every PR, with
branch protection. That core pipeline **already shipped**; what remains is the
hardening the issue and its siblings imply: no-network guarantees for the test
job, an authenticated-mode smoke test, the audit-chain verifier job (spec 03),
and the one-time branch-protection step.

## Current state (verified against the merged code, not the issue text)

`.github/workflows/ci.yml` (exists, do not rewrite from scratch):

## W1 — pytest `network` marker

```ini
[pytest]
markers =
    network: tests that perform real network access (deselected in CI)
```

2. Change the pytest step to `pytest -q -m "not network"`.
3. **No existing test needs the marker** (inventory above is clean). The rule
   going forward, added to README's dev section: any test performing real I/O
   (live sherlock/maigret/holehe scans, Stripe calls, spec 05's
   `scripts/load_test.py` if it ever becomes a test) must carry
   `@pytest.mark.network`.

## W2 — authenticated boot smoke

Extend the existing boot-smoke step (same job; do not add a job) with a
second server instance:

```yaml
      - name: Boot smoke with APP_PASSWORD gate
        run: |
          APP_PASSWORD=ci-test uvicorn app:app --host 127.0.0.1 --port 8001 &
          server_pid=$!
          trap 'kill $server_pid 2>/dev/null || true' EXIT
          for _ in $(seq 1 30); do
            curl -s -o /dev/null http://127.0.0.1:8001/api/sites && break || sleep 1
          done
          unauth=$(curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8001/api/sites)
          auth=$(curl -s -o /dev/null -w '%{http_code}' -u user:ci-test http://127.0.0.1:8001/api/sites)
          echo "unauth -> $unauth, auth -> $auth"
          test "$unauth" = "401"
          test "$auth" = "200"
```

The throwaway password `ci-test` hard-coded in the workflow is fine: it lives
only inside the runner process and gates nothing real. (The Basic gate accepts
any username, `app.py:108`.) This pins the `basic_auth_gate` middleware
behavior that spec 02's mode-flip logic builds on.

## W3 — audit-chain verification job (activates with spec 03)

Add a second job, either in the spec-03 PR or guarded so it self-activates:

```yaml
  audit-chain:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
          cache-dependency-path: requirements-dev.txt
      - run: pip install -r requirements-dev.txt
      - name: Append-only guard
        run: '! git grep -nE "UPDATE audit_log|DELETE FROM audit_log" -- "*.py"'
      - name: Intact chain verifies
        run: |
          python tests/fixtures/make_audit_fixture.py /tmp/audit_ok.db
          python scripts/verify_audit_chain.py --db /tmp/audit_ok.db
      - name: Tampered chain is rejected
        run: |
          python tests/fixtures/make_audit_fixture.py --tamper /tmp/audit_bad.db
          if python scripts/verify_audit_chain.py --db /tmp/audit_bad.db; then
            echo "verifier accepted a tampered chain"; exit 1
          fi
```

(Fixture generator and verifier are specified in spec 03.) If CI must merge
first, wrap the job steps with
`if: hashFiles('scripts/verify_audit_chain.py') != ''`.

## W4 — branch protection (one-time owner setup)

The check context is the job id: `test` today, plus `audit-chain` once W3 is
unguarded.

```bash
gh api repos/oduameh/sherlock-web/branches/main/protection \
  -X PUT \
  -f required_status_checks[strict]=true \
  -f required_status_checks[contexts][]=test \
  -f enforce_admins=false \
  -F required_pull_request_reviews=null \
  -F restrictions=null
```

Add `required_status_checks[contexts][]=audit-chain` after W3 lands — a
required check that never runs blocks all merges. Verify with:

```bash
gh api repos/oduameh/sherlock-web/branches/main/protection \
  --jq '.required_status_checks.contexts'
```

Issue acceptance test: open a PR with a deliberately failing test → merge
button blocked → close unmerged.

## Error behavior / operational notes

- CI must stay green on `main` at all times (branch protection enforces it
  for PRs; direct pushes to main should be considered off-limits socially,
  since `enforce_admins=false` keeps the owner's emergency path open).
- The boot smoke's 30s poll already absorbs the slow `SitesInformation()`
  import (`app.py:127`) — keep the poll when editing the step.
- Postgres-dependent tests (spec 01's optional matrix, spec 05's `SKIP
  LOCKED` claim path) are **not** in this pipeline; see open questions.
