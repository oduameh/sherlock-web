## Trust model (as implemented)

- **Single local user, no authentication by default.** `run.sh:21` binds `127.0.0.1:8420`; every route is open to whoever reaches the socket. The only gate is the optional shared `APP_PASSWORD` HTTP Basic check (`app.py:117-138`, constant-time compare `:129`, no lockout) — intended for Railway (`railway.json:7` binds `0.0.0.0`, `README.md:185-220`). On `0.0.0.0` without `APP_PASSWORD` the API and all stored PII are public.
- **The browser is trusted implicitly.** Because there is no Origin/Host/CSRF check (F-1), *any* web page the analyst opens — and, with tier 3, any page the tool itself renders — can drive the API. Reading responses cross-origin is prevented only by the same-origin policy, which DNS rebinding defeats in the absence of Host validation.
- **Everything fetched is untrusted input** and is handled as such for HTML/JSON parsing (try/except everywhere, size caps), but not for CPU time (F-3), decoded image size (F-4) or URL schemes rendered back to the analyst (F-6).
- **Environment is trusted:** `GODSEYE_URL` `app.py:1497`, `PROXY_LIST` `recon/router.py:489-492`, `DATABASE_URL` `dbconn.py:27`, `RECON_*` budgets. None are user-controllable at runtime; `_godseye_reachable` `app.py:1500-1510` is a one-shot TCP connect to an env-configured host and is **not** an SSRF vector.
- **Third parties receive subject data by design** (F-11); the "public data only" claim is accurate, the "denied hosts are never fetched" claim is not (F-2), and "no CAPTCHA bypass" is not accurate for tier 3 (F-7).
